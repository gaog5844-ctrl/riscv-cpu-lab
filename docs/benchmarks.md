# SIMD 性能测试

运行 `make bench`，Windows 中运行 `.\run.ps1 bench`。脚本执行点积、数组加法和矩阵向量乘法，记录标量与 SIMD 版本的仿真周期和指令数。

## 测试设置

两个版本使用同一份 `kernels.c`，通过宏切换实现。编译选项为 GCC `-O2`、RV32IM、ILP32，并禁用链接松弛。输入、输出的地址保持相同，脚本会检查这一点，以免代码大小影响数据缓存的组映射。

每次测试都重新复位，缓存和预测表从空状态开始。分支预测开启，分别测试缓存开关及 I/D 后端 1、5 周期延迟，不加入随机等待。

计时从 `kernel_start` 提交开始，到 `kernel_end` 提交前结束，包含调用、返回、访存、标量尾部计算和 FENCE 脏行写回。程序加载、输入生成和结果验证不在计时范围内。输入已经是 INT8，不包含浮点量化或外部数据搬运。

打包访问直接读取四字节对齐的连续字节数组。矩阵每行有 67 个有效元素，步长为 68 字节，填充字节不参与运算；两个版本使用相同布局。259 元素的数组和矩阵各行均有 3 个尾元素，由标量代码处理。当前结果不适用于未对齐的输入布局。

记录性能前，程序需通过 Python 期望值检查、C 结果检查、Spike 提交比较和 FENCE 后的全 RAM 比较。

## 缓存带来的开销

当前缓存填充一行需要 8 次串行字访问，没有突发传输、关键字提前返回或预取。短程序还要承担冷启动和结束时的脏行写回开销。

SIMD 将四次字节读取合为一次字读取，进一步减少了缓存能够节省的访问。例如，后端延迟为 1 周期时，`dot8` 的 SIMD 版本关闭缓存需要 895 周期，开启后增加到 1071 周期。这组测试中，缓存的填充和状态切换开销超过了命中带来的收益。

后续需要补充热缓存、更大输入和突发访存后端的测试。实际 DDR、布局布线后的频率、功耗和完整模型推理尚未测试。
