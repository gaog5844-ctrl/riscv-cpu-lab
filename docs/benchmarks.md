# SIMD 性能实验

make bench / .\run.ps1 bench 从真实 RTL 仿真生成周期，不使用估算或预置得分。

## 比较条件

- 同一 kernels.c 宏选择标量/SIMD；GCC -O2、RV32IM、ILP32、禁用链接松弛。
- 相同输入、输出地址，脚本实际核对，避免代码大小偷偷改变数据缓存映射。
- 每次复位，缓存/预测冷启动；预测开启，缓存开/关、I/D 延迟 1/5 周期，无随机等待。
- 从 kernel_start 提交到 kernel_end 提交前：包括调用/返回、加载/存储、标量尾部、最后 FENCE 脏写回。
- 不含程序加载、输入生成和结果验证。输入已是 INT8，不含浮点量化和外部搬运。
- 从四字节对齐的连续字节数组直接读取打包值，没有运行时预打包循环。矩阵有效 67 列、行步长 68，末尾填充不参与运算；两个版本布局相同。非对齐输入需重新测量。
- 259 元素数组和每行 67 元素矩阵均有 3 个尾元素，实际走标量代码。

Python 独立期望值、C 结果检查、Spike 逐提交、FENCE 后全 RAM 比较均通过，才记录性能。

## 为什么缓存有时变慢

填一行要 8 次串行字访问，没有 burst、关键字提前返回或预取。短程序还包含冷启动和末尾脏行排空。SIMD 已把四次字节读合成一次字读，缓存收益可能不足以抵消填充/状态转换开销。

例如 dot8 SIMD 延迟 1，关闭缓存 895 周期，开启 1071。这是当前实现和负载的限制，不可隐藏，也不代表缓存普遍无用。
