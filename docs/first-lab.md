# 首次运行与代码阅读

## 运行冒烟程序

在仓库目录打开 PowerShell：

~~~powershell
cd D:\Projects\riscv-cpu-lab
.\run.ps1 test
~~~

冒烟程序位于 `tests/programs/smoke.S`，依次执行加法、访存、循环、乘除和点积。正常结束时 a0 为 0，执行 EBREAK；失败路径会先把 a0 设为 1。

## 看提交记录

打开 `build/smoke-l1-p1.csv`。每行对应一条到达提交阶段的指令，`cycle` 为十进制，其余字段为十六进制。

|字段|含义|
|---|---|
|`pc` / `insn`|指令地址和机器码|
|`rd` / `data`|目的寄存器和写回值|
|`npc`|执行后的下一 PC|
|`trap` / `cause`|是否异常及异常原因；本程序用 cause=3 的 EBREAK 结束|

程序开头将 35 和 7 相加，结果 42 写入 t2，再通过 SW 和 LW 存入、读回 `scratch`。随后再加 7，得到 49。对照 CSV 时，这两个结果分别显示为 `2a` 和 `31`。

这几条指令适合用来检查 ALU 结果、存储数据和加载后的前递。

## 看波形

运行 `.\run.ps1 wave`，再按 [环境配置](toolchain.md) 中的命令打开 GTKWave。

先添加 `clk`、`commit_valid`、`commit_pc`、`commit_rd` 和 `commit_data`，找到前面的加法和访存。再加入核心中的 `e_valid/m_valid/w_valid`、`load_hazard` 和 `redirect`，观察这些指令在哪一拍进入或离开各级。

时钟沿到来前，组合逻辑形成结果；时钟沿将结果写入下一级寄存器。缓存等待、除法和分支冲刷都会使提交之间出现空拍。

## 改一个输入

把 `smoke.S` 中的 35 改成 36，保留原来的预期值 49，测试应进入失败路径。再把预期值改成 50，重新运行测试。

接着比较关闭预测器或增加内存延迟的结果。`tests/run_smoke.py` 已包含三种延迟与预测开关组成的六组配置；同一程序的结果应一致，周期数会变化。

## 阅读 RTL

建议从运算和译码开始，再看流水级之间的数据传递：

1. `rv32_alu.sv`：ALU 操作和输入、输出。
2. `rv32_decode.sv`：机器码、立即数和控制信号。
3. `rv32_core.sv`：`e/m/w` 结构体、流水级握手、前递和冲刷。
4. `rv32_dcache.sv`：状态机、数据阵列、字节使能和写回。
5. `rv32_bpu.sv`：标签、两位计数器和预测目标。
6. `rv32_simd.sv` 与 `sw/include/xsimd.h`：自定义指令的硬件运算和 C 调用。

读核心时可以沿着两个问题查代码：加载未命中时，除法器如何等待它的操作数？分支改变方向后，后面的存储指令如何被取消？
