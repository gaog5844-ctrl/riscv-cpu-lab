# Xsimd：定长打包整数扩展

把 32 位寄存器当四个 8 位格子或两个 16 位格子，一条指令同时处理多个格子。仍只发射/提交一条指令，与同周期发射两条普通指令不同。

R 型编码：opcode=0x0B（custom-0），funct7=0，rd/rs1/rs2 都是普通整数寄存器。

|指令|funct3|语义|
|---|---:|---|
|xadd8|0|四路独立模 256 加法，进位不串到邻居|
|xadd16|1|两路独立模 65536 加法|
|xdot8|2|四对有符号 INT8 相乘求和，得到一个 32 位整数|

低位在前，[1, 2, -3, 4] 与 [5, -6, 7, 8] 的点积为 4。xdot8 **不加旧 rd**，需要累加时再 ADD。xadd8 的一个格子 255+2 得到 1，不饱和到 255；xdot8 的格子范围为 -128 到 127。

## C 调用

~~~c
#include "sw/include/xsimd.h"
int32_t partial = xdot8(packed_a, packed_b);
sum += partial;
~~~

使用 GCC .insn 编码，不维护编译器分支。标准 objdump 显示 .insn 而非新助记符是正常现象。编译仍使用 -march=rv32im -mabi=ilp32，不能写成 rv32imv。

只能在启用 Xsimd 的本核心或加载 sim/spike_xsimd.cpp 扩展的 Spike 中执行；普通 RV32IM CPU 会产生非法指令。

## 创新边界

没有向量寄存器、VL/VTYPE、掩码、可变向量长度、向量访存或自动向量化，不能称作 RVV。本期是面向 INT8 点积的定长 SIMD，加上完整参考模型、C 封装和实测链。

增加流水段数可能降低每级延迟，也增加分支恢复/前递成本，必须测综合与布局布线后频率。双发射还需双指令相关检查、双写口和资源冲突处理。当前先用小扩展隔离变量测收益，不同时改动这三条路线。

点积与量化推理有关，但这里只实现一个算子片段，没有模型加载、量化流程、运行时或足够内存，不能声称支持完整大模型。下一步优先板级时序/资源及缓存后端，再评估更深流水或双发射。
