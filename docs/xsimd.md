# SIMD 指令

Xsimd 使用 32 位通用寄存器保存四个 8 位整数，或两个 16 位整数。一条指令完成多个数据通道的运算，处理器仍然是单发射。

## 编码和语义

三条指令都使用 R 型编码：`opcode=0x0B`（custom-0），`funct7=0`。`rd`、`rs1`、`rs2` 均为普通整数寄存器。

|指令|funct3|运算|
|---|---:|---|
|`xadd8`|0|四路独立模 256 加法，各通道之间不传递进位|
|`xadd16`|1|两路独立模 65536 加法|
|`xdot8`|2|四对有符号 INT8 相乘后求和，结果为一个 32 位整数|

按低位到高位的顺序，将 [1, 2, -3, 4] 和 [5, -6, 7, 8] 分别打包，`xdot8` 得到的结果为 4。指令只计算本次点积，不累加原来的 `rd`；需要累加时，再执行 ADD。

`xadd8` 和 `xadd16` 都是截断加法，没有饱和处理。例如 `xadd8` 中一个通道的 255+2 得到 1。`xdot8` 按 -128 到 127 解释每个输入字节。

## C 调用

~~~c
#include "sw/include/xsimd.h"
int32_t partial = xdot8(packed_a, packed_b);
sum += partial;
~~~

头文件使用 GCC `.insn` 生成编码，无需修改编译器。编译选项仍为 `-march=rv32im -mabi=ilp32`。标准 objdump 未识别这些助记符时，会显示 `.insn`。

程序需要在启用 Xsimd 的本核心，或加载 `sim/spike_xsimd.cpp` 扩展的 Spike 中执行。普通 RV32IM 处理器会将这些编码作为非法指令处理。

## 设计选择

这组扩展针对固定宽度的整数运算，复用现有寄存器和提交路径，便于比较加入指令前后的性能。它没有向量寄存器、VL/VTYPE、掩码、可变向量长度或向量访存，与标准 RVV 不兼容。

本版本保留五级单发射结构。加深流水线会改变前递和分支恢复的代价；双发射还需要指令相关检查、双写口和资源冲突处理。这两项需要结合综合后的时序与资源占用另做评估。

INT8 点积可以用于量化推理中的部分计算，但项目尚无模型加载、量化流程或推理运行时。
